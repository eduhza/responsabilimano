# Envio real de e-mail (SMTP) + base URL nos links

## User Value
Como usuário, quero que os e-mails do sistema (convite, recuperação de senha e
check-in) sejam de fato entregues, com links que funcionem em produção — não
apenas escritos no log.

## Contexto
`IEmailService` só tinha `LoggingEmailService` (escreve no log). Sem transporte
real, as notificações de check-in (S3.3/S3.4) iriam ao ar mudas ao ligar a flag.
Além disso, `PasswordResetService` montava o link com `https://localhost:8080`
fixo — link quebrado em produção assim que o e-mail real fosse ativado.

## Acceptance Criteria
1. `SmtpEmailService : IEmailService` via MailKit (STARTTLS na porta 587,
   autenticação usuário/senha, corpo HTML, From = `FromName <FromEmail>`).
2. Config em `EmailSettings` (`SmtpHost`, `SmtpPort`, `SmtpUser`, `FromName`,
   `FromEmail`); **senha só via `EmailSettings__SmtpPassword`** (Secret Manager),
   nunca no Git.
3. Seleção do serviço por presença de senha: com senha → SMTP; sem senha (dev
   local) → `LoggingEmailService` (fallback seguro, sem depender de
   `ASPNETCORE_ENVIRONMENT`).
4. Link de recuperação de senha montado a partir do `baseUrl` da requisição
   (mesmo padrão do convite), removendo o `localhost:8080` fixo.
5. Sem PII em logs (o `SmtpEmailService` não loga o destinatário).

## Data Model
- Sem mudança.

## Security Constraints
- Senha do SMTP apenas no Secret Manager (`EmailSettings__SmtpPassword`).
- MailKit/MimeKit em versão sem vulnerabilidade conhecida (gate SCA verde).

## API / Event Contract
- none.

## Dependencies
- Nenhuma. Habilita o Gate 3 do Sprint 3 (envio real das notificações de check-in).

## Out of Scope
- Fila/retry de e-mail, templates ricos, bounce handling (pós-MVP).

## Verification
- `dotnet test`: `BuildMessage` mapeia From/To/Subject/HTML; link de reset usa o baseUrl.
- Smoke E2E no ambiente: `forgot-password` entrega o e-mail com link correto.
