# Cronjob de envio de check-in

## User Value
Como sistema, quero disparar e-mails de check-in na frequência do projeto para
lembrar a dupla de preencher.

## Acceptance Criteria
1. Endpoint HTTP protegido por secret header (ex.: `X-Cron-Secret`) que dispara o
   processamento — chamado pelo Cloud Scheduler no GCP.
2. Processa apenas projetos `Em Andamento` cuja data de fim não passou.
3. Para cada projeto elegível no período, envia e-mail aos dois participantes via
   `IEmailService`, com link para a tela de check-in (token/link mágico).
4. Respeita `Project.Frequency` (Daily/Weekly/Biweekly/Monthly; padrão sexta 08h).
5. Idempotente: rodar duas vezes no mesmo período não duplica envios.
6. Contrato de evento `checkin-events.yaml` (AsyncAPI) descreve o disparo.

## Data Model
- Pode exigir marcação de "período processado" para idempotência.

## Security Constraints
- Endpoint de cron **não** é público: exige secret header (documentar no ADR se
  usar `DisableAntiforgery`). Sem PII em logs (logar id, não e-mail).

## API / Event Contract
Ver contracts/checkin-events.yaml (AsyncAPI) e o endpoint protegido no OpenAPI.

## Dependencies
- S3.1 (modelo). Idealmente S3.2 (tela destino do link).

## Out of Scope
- Lembretes de não-resposta (S3.4).

## Verification
- Teste do serviço: seleção de projetos elegíveis + idempotência.
- Manual: chamar o endpoint com o secret e ver e-mails logados (dev).
