# Tela de check-in

## User Value
Como usuário, quero preencher meu check-in do período (métricas + sentimento)
para registrar meu progresso no projeto.

## Acceptance Criteria
1. Formulário gerado dinamicamente a partir dos `GoalField` do projeto,
   respeitando `DataType`, `Unit`, `MinValue`, `MaxValue`.
2. Seletor de sentimento com 5 rostos (SVG), mapeando para o enum `Feeling`.
3. Acessível por link (com ou sem login — ver S3.3 para o token de link mágico).
4. Endpoint `POST /api/projects/{id}/checkins` persiste `CheckIn` + `CheckInMetric`.
5. Um check-in por usuário por período (rejeita duplicado com mensagem clara).
6. Validação de limites por campo (server-side) e do vínculo do usuário ao projeto.

## Data Model
- Usa `CheckIn`/`CheckInMetric` de S3.1.

## Security Constraints
- Só participante do projeto grava check-in. Validar limites server-side.
  Antiforgery ativo no form interativo. Sem PII em logs.

## API / Event Contract
Adicionar `POST /api/projects/{id}/checkins` ao contrato (ver R9).

## Dependencies
- S3.1 (modelo). X1 (render mode) para o formulário funcionar no navegador.

## Out of Scope
- Envio de e-mail/cron (S3.3), lembretes (S3.4), dashboard (Sprint 4).

## Verification
- Teste de integração do endpoint (happy path + duplicado + fora de limite).
- Manual: preencher check-in pela UI e ver persistido.
