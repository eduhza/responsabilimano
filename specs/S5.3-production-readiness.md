# Produção — Domínio, Deploy Manual e Backup do Banco

## User Value
Como PM/operador, quero a aplicação acessível por um domínio próprio com HTTPS,
um manual de deploy reproduzível e um script de backup do banco para que o MVP
esteja pronto para uso real com segurança operacional.

## Contexto
A aplicação já roda no GCP Cloud Run com Cloud SQL PostgreSQL. O deploy é
automatizado via GitHub Actions (merge para `main`). No entanto:
- O acesso é pelo URL default do Cloud Run (`*.run.app`), sem domínio próprio.
- Não há documentação de deploy manual (para recuperação de desastre).
- Não há backup automatizado do banco.

## Acceptance Criteria
1. **Manual de deploy.** Criar `docs/deploy-manual.md` com:
   - Pré-requisitos: `gcloud` CLI autenticado, acesso ao projeto
     `responsabilimano`, Docker.
   - Deploy automatizado (CI/CD): o que acontece no merge para `main`, quais
     secrets são lidos, qual comando o CI executa.
   - Deploy manual (passo a passo): build da imagem, push para o Artifact
     Registry, `gcloud run deploy` com os flags corretos (referenciando
     `docs/environment-variables.md` para env-vars e secrets).
   - Rollback: como reverter para uma revisão anterior do Cloud Run
     (`gcloud run revisions roll back` ou `gcloud run deploy --image <old-sha>`).
   - Verificação pós-deploy: checar `/health`, `/health/ready` e smoke test
     manual (registrar, login, criar projeto).
2. **Script de backup do banco.** Criar `scripts/backup-cloudsql.sh` (bash) que:
   - Exporta o banco Cloud SQL PostgreSQL para um arquivo `.sql` usando
     `gcloud sql export sql` (ou `pg_dump` via Cloud Shell).
   - Nomeia o arquivo com timestamp: `responsabilimano-YYYYMMDD-HHMMSS.sql`.
   - Faz upload para um bucket GCS (ex: `gs://responsabilimano-backups/`).
   - Mantém apenas os últimos 30 dias (opcional: `gsutil -m rm` baseado em
     idade; documentar como configurar via lifecycle do bucket).
   - Documentar no `docs/deploy-manual.md` como agendar o backup via Cloud
     Scheduler ou cron do sistema operacional.
3. **Configuração de domínio/SSL (documentação + comando).** Documentar em
   `docs/deploy-manual.md` os passos para mapear um domínio customizado ao
   serviço Cloud Run:
   - `gcloud run domain-mappings create --service <service> --domain <domain>
     --region <region>`.
   - Verificar propagação DNS (CNAME ou A record apontando para o Cloud Run).
   - SSL é provisionado automaticamente pelo Google Managed Certificates.
   - Nota: o domínio real e os registros DNS são configurados pelo PM fora da
     aplicação; a spec documenta o processo.
4. **Atualizar README.** O `README.md` reflete o estado atual do projeto:
   - Como rodar localmente (`docker-compose up`).
   - Link para `docs/deploy-manual.md` (deploy).
   - Link para `docs/environment-variables.md` (configuração).
   - Status atual do projeto (MVP em produção).
5. **Feature flags de produção.** Documentar no `docs/deploy-manual.md` quais
   feature flags estão ativas em produção (`FeatureManagement__CheckIns=true`,
   `FeatureManagement__Dashboard` — depende de S4.2) e como ligar/desligar via
   `gcloud run services update --set-env-vars`.

## Data Model
- Sem mudança.

## Security Constraints
- O script de backup não contém credenciais — usa a autenticação do `gcloud` CLI.
- O bucket GCS de backups deve ter acesso restrito (não público). Documentar
  isso no script.
- O manual de deploy não inclui valores de secrets — apenas nomes e referências
  ao Secret Manager.

## Out of Scope
- Setup real do domínio DNS (feito pelo PM fora da aplicação).
- Provisionamento do bucket GCS (feito pelo PM via `gsutil mb`).
- Monitoramento/observabilidade avançada (Datadog, Prometheus) — pós-MVP.
- CI/CD para ambientes de staging — pós-MVP.
- Migração de schema em produção (já coberta pelo EF Core migrations no startup
  da aplicação).
