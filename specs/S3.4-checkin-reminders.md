# Lembretes de check-in não respondido

## User Value
Como usuário, quero receber um lembrete por e-mail se eu não preencher o check-in
no prazo, para não perder o período.

## Acceptance Criteria
1. Job secundário (endpoint protegido por secret, acionado pelo Scheduler) que,
   após o prazo do período, identifica participantes sem check-in.
2. Envia lembrete via `IEmailService` apenas aos pendentes.
3. Não envia lembrete a quem já preencheu, nem a projeto fora de `Em Andamento`.
4. Idempotente: no máximo um lembrete por participante por período.

## Data Model
- Reutiliza `CheckIn` (ausência = pendente). Pode marcar "lembrete enviado".

## Security Constraints
- Mesmo esquema de secret do S3.3. Sem PII em logs.

## API / Event Contract
Ver contracts/checkin-events.yaml (evento de lembrete).

## Dependencies
- S3.1 (modelo) e S3.3 (cron base).

## Out of Scope
- Escalonamento/segundo lembrete configurável (pós-MVP).

## Verification
- Teste do serviço: identifica pendentes corretamente e não duplica.
