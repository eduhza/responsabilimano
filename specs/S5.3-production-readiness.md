# Produção — Domínio, Deploy Manual e Backup do Banco

## User Value
Como PM/operador, quero a aplicação rodando com estabilidade e o menor custo possível no GCP. Preciso de um manual de deploy reproduzível e um script de backup do banco enviando dados para o Cloud Storage, garantindo a segurança do MVP sem estourar o orçamento.

## Contexto
A aplicação já roda no GCP Cloud Run com Cloud SQL PostgreSQL. O deploy é automatizado via GitHub Actions (merge para `main`). No entanto:
- Não há documentação de deploy manual (para recuperação de desastre) e documentação de setup do banco de dados focado em baixo custo.
- Não há backup automatizado do banco de dados exportado para GCS (aproveitando o Free Tier).

## Acceptance Criteria
1. **Manual de deploy e Infraestrutura.** Criar `docs/deploy-manual.md` com:
   - Pré-requisitos: `gcloud` CLI autenticado, acesso ao projeto `responsabilimano`, Docker.
   - **Setup Cloud SQL (Custo Mínimo):** Documentar a criação/revisão da instância com os seguintes parâmetros obrigatórios para o MVP:
     - Máquina: `db-f1-micro` (Shared core).
     - Armazenamento: HDD (Standard) de 10GB.
     - Disponibilidade: Zonal (Single zone), desativar High Availability (HA).
     - Backups automáticos nativos: **Desativados** (para evitar cobrança de storage do Cloud SQL, usaremos o script via GCS).
   - Configuração de Rede: Documentar o uso de **Direct VPC Egress** no Cloud Run para acesso ao banco, proibindo o uso de Serverless VPC Connectors.
   - Deploy automatizado (CI/CD): o que acontece no merge para `main`, quais secrets são lidos.
   - Deploy manual (passo a passo): build, push para o Artifact Registry, `gcloud run deploy`.
   - Rollback: como reverter para uma revisão anterior.

2. **Script de backup do banco.** Criar `scripts/backup-cloudsql.sh` (bash) que:
   - Exporta o banco Cloud SQL PostgreSQL para um arquivo `.sql` usando `gcloud sql export sql`.
   - Nomeia o arquivo com timestamp: `responsabilimano-YYYYMMDD-HHMMSS.sql`.
   - Faz upload para um bucket GCS restrito. **Importante:** O script/documentação deve exigir que o bucket seja criado em `us-central1`, `us-east1` ou `us-west1` para utilizar os 5GB do Free Tier permanente.
   - Mantém apenas os últimos 30 dias (documentar como configurar via lifecycle rules do bucket).
   - Documentar como agendar a execução desse script (ex: Cloud Scheduler).

3. **Configuração de domínio/SSL (Opcional).** Documentar no `docs/deploy-manual.md` os passos para mapear um domínio customizado:
   - Registrar que o domínio customizado exige compra em registrador externo. Para custo zero, é encorajado o uso da URL default `*.run.app` no MVP.
   - Passos para mapeamento via `gcloud run domain-mappings create`, caso o PM decida prosseguir.

4. **Atualizar README.** O `README.md` reflete o estado atual do projeto:
   - Como rodar localmente (`docker-compose up`).
   - Links para `docs/deploy-manual.md` e `docs/environment-variables.md`.
   - Status atual do projeto (MVP em produção).

5. **Feature flags de produção.** Documentar no `docs/deploy-manual.md` quais feature flags estão ativas em produção (`FeatureManagement__CheckIns=true`, `FeatureManagement__Dashboard` — depende de S4.2) e como ligar/desligar via `gcloud run services update --set-env-vars`.
