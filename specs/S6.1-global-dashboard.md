# Painel global do usuário (`/dashboard`)

## User Value
Como usuário com mais de um projeto, quero uma tela `/dashboard` com números
consolidados de todos os meus projetos e um card por projeto, para saber onde
estou pendente sem abrir cada projeto — e quero que `/projects/{id}/dashboard`
continue sendo apenas a comparação daquele projeto.

## Acceptance Criteria
1. `/dashboard` renderiza `GlobalDashboard.razor` com `@rendermode InteractiveServer`
   e `@attribute [Authorize]` (X1/ADR-0003), e lista **apenas** projetos em que o
   usuário é criador ou parceiro.
2. `IDashboardService.GetGlobalDashboardAsync(userId)` retorna KPIs consolidados
   corretos: total de projetos, projetos ativos, check-ins enviados pelo usuário,
   sequência atual e recorde (a melhor entre os projetos do usuário) e quantidade
   de check-ins abertos no período corrente.
3. Cada projeto aparece como um card com ícone, nome, status, a dupla, progresso
   (`período X de Y`), último humor registrado pelo usuário e marcação de
   "check-in pendente" quando o período corrente ainda não foi preenchido.
4. Usuário sem projetos vê um empty state com CTA para `/projects/new`.
5. `/projects/{id}/dashboard` continua exclusiva do projeto: título de comparação
   ("Evolução lado a lado"), subtítulo com o progresso do projeto, e nenhum número
   agregado de outros projetos.
6. Com a flag `Dashboard` desligada: `/dashboard` responde como não encontrado, o
   item "Painel" da navegação volta a ser placeholder e `GET /api/dashboard`
   responde 404.
7. `GET /api/dashboard` responde 401 sem cookie de autenticação e 200 com o
   `GlobalDashboardResponse` do usuário autenticado.
8. Todos os textos visíveis externalizados em `AppStrings.resx` e
   `AppStrings.pt-BR.resx`.

## Data Model
- Sem mudança de esquema/migrations. Novos DTOs de leitura:
  - `GlobalDashboardResponse(TotalProjects, ActiveProjects, TotalCheckIns,
    CurrentStreak, BestStreak, OpenCheckIns, Projects)`
  - `GlobalProjectSummary(ProjectId, Name, Icon, Status, StartDate, EndDate,
    Frequency, CreatorName, PartnerName, CurrentPeriod, TotalPeriods,
    CheckInsSubmitted, CheckInPending, LatestFeeling, GoalCount)`
- `StreakCalculator` (Core/Common) extraído de `ProjectService.GetStreakAsync`
  para que a regra de sequência exista em um único lugar.

## Security Constraints
- Página `[Authorize]`; endpoint exige `TryGetAuthenticatedUserId` (401 sem cookie).
- A consulta filtra por participação (`CreatorId == userId || PartnerId == userId`),
  então não há como enumerar projetos alheios — não existe id na entrada.
- Logs sem PII: apenas `userId` e contagens.
- Grupo de endpoint atrás de `RequireFeature(FeatureFlags.Dashboard)` (spec R7).

## API / Event Contract
Ver `contracts/responsabilimano-api.yaml` — `GET /api/dashboard`
(`operationId: getGlobalDashboard`, tag `Dashboard`, 200/401/404).

## Out of Scope

- Destino global para "Check-in" (continua dependendo de um projeto).
- Mudanças de modelo de dados/migrations.
