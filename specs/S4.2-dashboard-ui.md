# Dashboard UI — Gráfico de Evolução e Cards de Sentimento

## User Value
Como participante de um projeto ativo, quero visualizar um dashboard com o
gráfico comparativo de evolução das metas e cards de sentimento/adesão de ambos
os participantes, para acompanhar a evolução da dupla e me manter motivado.

## Acceptance Criteria
1. Rota `/projects/{id}/dashboard` renderiza a página `Dashboard.razor` com
   `@rendermode InteractiveServer` e `@attribute [Authorize]` (seguindo X1/ADR-0003).
2. A página injeta `IDashboardService` (definido em S4.1) e chama
   `GetDashboardAsync(projectId, userId)` para obter o `DashboardResponse`.
   Exibe:
   - **Gráfico de linha** (Chart.js via JS interop) comparando os dois
     participantes ao longo do tempo para cada `GoalField`. Eixo X = período
     (`PeriodNumber`); eixo Y = valor. Uma linha por usuário.
   - **Cards de sentimento**: para cada participante, o rosto SVG (mesmo conjunto
     de 5 faces do `CheckIn.razor`) correspondente ao `LatestFeeling`. Se `null`,
     exibir placeholder "sem check-ins".
   - **Cards de média**: para cada `GoalField` x participante, o `AverageValue`
     com label e unidade. Se `null`, exibir "—".
3. O gráfico Chart.js é carregado via `<script src="...">` no `App.razor` ou na
   página, e inicializado via `IJSRuntime.InvokeVoidAsync`. A biblioteca Chart.js
   (MIT) é referenciada via CDN ou arquivo local em `wwwroot/lib/chart.js/`.
4. Um seletor (dropdown ou abas) permite escolher qual `GoalField` visualizar no
   gráfico (quando ha mais de uma meta). Default = primeira meta.
5. A página exibe loading state enquanto os dados não chegaram e mensagem de erro
   se a chamada falhar.
6. A página é responsiva (mobile e desktop) — gráfico com `max-width: 100%`,
   cards em grid que colapsa em mobile.
7. Um link "Voltar ao projeto" leva para `/projects/{id}`.
8. Um botão/link "Dashboard" aparece na `ProjectDetail.razor` quando o projeto
   esta `Active` e a flag `Dashboard` esta on (mesmo padrao do botão de check-in).
9. Todos os textos visíveis são externalizados em `AppStrings.resx` /
   `AppStrings.pt-BR.resx` (i18n).
10. A feature flag `Dashboard` (mesma flag de S4.1) controla a visibilidade da
    página e do botão na `ProjectDetail`. Quando off, a rota responde 404.

## Data Model
- Sem mudança. Consome o `DashboardResponse` de S4.1.

## Security Constraints
- Página protegida (`@attribute [Authorize]`).
- O endpoint ja valida participação (S4.1).
- Sem PII em logs. Antiforgery não aplicável (GET + render).

## API / Event Contract
Consome `GET /api/projects/{id}/dashboard` definido em S4.1.
Sem novos endpoints.

## Dependencies
- S4.1 (Dashboard Data API — endpoint e DTOs).
- X1 (render mode interativo — `@rendermode InteractiveServer`).

## Out of Scope
- Histórico/linha do tempo detalhada (PRD E4-U4 — desejo, não MVP).
- Exportação de dados ou relatórios PDF.
- Filtros por intervalo de datas customizável.
- Gráficos adicionais (barra, radar, etc.) — apenas linha.

## Verification
- Manual: criar projeto, convidar parceiro, aprovar, preencher 2+ check-ins para
  ambos os usuários, navegar para `/projects/{id}/dashboard` e verificar:
  - Gráfico renderiza com 2 linhas (uma por usuário).
  - Cards de sentimento mostram o rosto correto.
  - Cards de média mostram o valor correto.
  - Seletor de meta troca o gráfico.
  - Layout responsivo no mobile (DevTools).
- Teste bUnit (se viável): verificar que o componente renderiza estado de loading
  e estado de erro.
- `dotnet build` e `dotnet test` verdes.
