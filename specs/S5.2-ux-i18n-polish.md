# UX, Mensagens e i18n — Polimento do MVP

## User Value
Como usuário, quero mensagens claras (telas e e-mails), feedback visual em todas
as interações e textos externalizados para que a aplicação seja usável e pronta
para novos idiomas.

## Contexto
As telas Blazor já usam `IStringLocalizer<AppStrings>` com ~110 chaves em
`AppStrings.resx` (en) e `AppStrings.pt-BR.resx` (pt-BR). No entanto, os **templates
de e-mail** em `ProjectService`, `PasswordResetService` e `CheckInNotificationService`
têm strings em português hard-coded (não externalizadas). Algumas telas podem não
ter feedback visual consistente (loading/erro/sucesso).

## Acceptance Criteria
1. **Templates de e-mail externalizados.** Os subjects e corpos HTML dos 4 e-mails
   transacionais são movidos para templates externalizados (não necessariamente
   `.resx` — pode ser arquivos `.html` em `wwwroot/email-templates/` ou strings
   em um `EmailTemplates` static class com `IStringLocalizer`). Os 4 e-mails:
   - Convite de projeto (`ProjectService.InvitePartnerAsync`)
   - Recuperação de senha (`PasswordResetService.RequestResetAsync`)
   - Notificação de check-in (`CheckInNotificationService.SendCheckInRequestEmailAsync`)
   - Lembrete de check-in (`CheckInNotificationService.SendReminderEmailAsync`)
2. **Revisão de textos de e-mail.** Corrigir acentuação ausente nos templates
   atuais (ex: "Voce" → "Você", "Ola" → "Olá", "Recuperacao" → "Recuperação").
   Garantir tom consistente e profissional.
3. **Audit de i18n nas telas.** Garantir que 100% dos textos visíveis nas páginas
   Razor usem `@Localizer["Key"]` ou `Localizer["Key"]`. Textos hard-coded em
   português (se encontrados) são movidos para `.resx`. O `Error.razor` e
   `ReconnectModal.razor` (templates do framework) são out-of-scope.
4. **Feedback visual consistente.** Todas as páginas interativas (com
   `@rendermode InteractiveServer`) que fazem chamadas assíncronas exibem:
   - **Loading**: estado visual enquanto a operação está em andamento (spinner
     ou texto "Carregando..."/"Processando..."). Já existe em Dashboard e
     ProjectDetail; verificar e completar em CreateProject, InvitePartner,
     CheckIn, ForgotPassword, ResetPassword, InvitationAccept.
   - **Erro**: `div.alert-danger` com mensagem localizada (já existe na maioria;
     auditar e completar).
   - **Sucesso**: `div.alert-success` com mensagem localizada (já existe na
     maioria; auditar e completar).
5. **Estrutura i18n pronta para novos idiomas.** O `AppStrings.resx` (fallback en)
   e `AppStrings.pt-BR.resx` estão sincronizados (mesmas chaves). Documentar no
   `docs/environment-variables.md` como adicionar um novo idioma (criar
   `AppStrings.<culture>.resx` e configurar `RequestLocalizationOptions`).
6. **Testes.** Os testes bUnit existentes (`DashboardTests`, `RegisterTests`)
   continuam verdes. Adicionar pelo menos um teste bUnit que verifica que uma
   página interativa (ex: `CreateProject` ou `InvitePartner`) renderiza estado de
   loading antes do resultado. Os testes E2E existentes continuam verdes (os
   seletores por texto em português continuam funcionando pois pt-BR é a cultura
   padrão).

## Data Model
- Sem mudança.

## Security Constraints
- Templates de e-mail não incluem PII além do nome do destinatário (que já é
  usado hoje). Não logar o conteúdo do e-mail.
- A externalização de templates não introduz path traversal — se usar arquivos
  `.html`, carregar de um diretório fixo (`wwwroot/email-templates/`) sem input
  do usuário no path.

## API / Event Contract
- none. Sem novos endpoints.

## Dependencies
- Nenhuma. Pode ser executada independentemente.

## Out of Scope
- Tradução para outros idiomas além de pt-BR e en (apenas a estrutura deve estar
  pronta).
- Redesign visual / novo tema.
- Templates de e-mail ricos (com CSS inline, logos, etc.) — apenas externalizar
  e revisar os textos existentes.
- Acessibilidade (WCAG) — fica para pós-MVP.
